# 改善案6件の実装・実証検証レポート (2026-07)

6つの改善案をそれぞれ独立ブランチ+独立仮想環境で実装し、**このリポジトリの実コード**
(`examples/mock_problem` の焼きなましソルバー、および実際の `worker.py` / `supervise_slots.py`
プロセス起動)を用いて検証した。全ての数値は各ブランチの `experiments/results_*.json` に
生データがあり、`experiments/validate_*.py` で再現できる。憶測による評価は含まない。

- 検証環境: Linux / Python 3.11.15 / 4コア。ブランチ n は venv n(1,3,4: optuna、5: optuna+HEBO 0.3.6、2,6: 標準ライブラリ)。
- 探索系検証 (V1,V3,V4,V5) の目的関数: mock_problem の5インスタンスseed平均スコア(最大化)。
  `iters` の探索上限は600に制限した。**上限20000ではランダム設定の中央値でも最適値72.767に
  到達して目的関数が飽和し、手法間の差が測定不能になることを事前実験で確認した**ため
  (本戦も制限時間でitersは上限張り付きになり、実際の調整対象はt0/cooling)。
- 区間推定は全てブートストラップ95%CI。

## 詳細

### 1. TPE推奨設定 — `--tpe-profile recommended` を既定化
30rep×60trial、バッチ8のask/tell(本番ブリッジと同じ並列形態)。
- best@30: default 72.635±0.081 / recommended 72.671±0.052、対差 +0.0359 (95%CI [+0.0005, +0.0696])
- best@60: default 72.688±0.051 / recommended 72.716±0.027、対差 +0.0282 (95%CI [+0.0108, +0.0461])、22勝8敗
- ばらつき(rep間sd)が約半分になる点も実務上重要(=当たり外れが減る)。
数行の変更でリスクは `--tpe-profile default` で即時復元可能。

### 2. IQM+CI — 「CIは有効、IQM点推定は本ワークロードでは逆効果」
実ソルバーのスコアプール(config×5インスタンス×60 sa-seed)から本番と同じ形の
少数run標本を4000回引き、真値(大標本平均)に対する誤判定率を測定。

| 真のギャップ | n | mean誤判定 | IQM誤判定 | CI宣言率 | CI宣言時精度 |
|---|---|---|---|---|---|
| 0.14σ | 5 | 24.3% | 28.4% | 0% | (宣言なし) |
| 0.14σ | 15 | 11.4% | 16.2% | 16.6% | 98.2% |
| 0.45σ | 5 | 3.8% | 6.5% | 0% | (宣言なし) |
| 0.45σ | 15 | 0.05% | 0.35% | 64.7% | 100% |
| 0.99σ | 15 | 0% | 0% | 98.1% | 100% |

- 本ソルバーのスコア分布ではIQM点推定がmeanを上回った条件は一つもなく、差がある全条件で悪化した(分布の裾が情報を持つため)。
  → **既定aggはmeanに戻した**(iqmはオプションとして残置)。
- 一方CI非重複ルールは「差がないときは判定を保留し、宣言したときはほぼ間違えない」
  という理想的なガードレールとして機能。n=5では小〜中差で一度も誤宣言しなかった
  (=「5runでは足りない」を正しく教えてくれる)。
- 原論文(Agarwal et al.)の主張のうち**区間推定の採用**は本環境でも支持され、
  **IQMの点推定**は支持されなかった。文献のバイアスではなく実測に従う。

### 3. successive halving — 現構成では不採用
同一のseed評価予算(400回)で full(常に5seed)対 halving(rungs=[1,2,5], eta=3)。
- best@400: full 72.724±0.029 / halving 72.682±0.047、対差 −0.0424 (95%CI [−0.063, −0.021])
- best@200 でも −0.0369 (95%CI [−0.064, −0.011])
インスタンスが5個しかない構成では、1seed評価のノイズによる誤淘汰の損失が
候補数増加の利得を上回った。DEHB等の原論文が扱う「低予算評価でも順位相関が
高い」状況(epoch数やデータサイズが忠実度)とは条件が異なる。
インスタンス数が大きい本戦条件(例: 20seed以上)では再検証の価値はあるが、
**現状の実測が悪化を示す以上、mainには入れない**。コードはブランチに残す。

### 4. 事前分布注入 — 短期決戦で有効、誤priorにも頑健
good/bad prior は憶測ではなく実測200点のランダム探索から選定
(最良点 iters=485, t0=4.43, cooling=0.0053 / 最悪点 iters=169, t0=33.8, cooling=0.35)。
24rep×30trial、confidence=0.9、β/(β+t)減衰。
- best@10: none 72.523±0.116 / good 72.624±0.089 (+0.101, 95%CI [+0.038, +0.158]) / bad 71.758±1.397 (−0.765)
- best@30: good +0.006 (95%CI [−0.025, +0.037]) / bad −0.018 (95%CI [−0.052, +0.015])
→ 正しい勘は序盤を有意に加速し、誤った勘でも30trialで統計的に区別できない水準まで
回復(πBO論文の頑健性主張と整合する実測)。priorを書かなければ挙動は完全に従来どおり。

### 5. HEBO — 有意に良いが、導入コストと計算オーバーヘッドに注意
10rep×40trial、バッチ4。
- best@20: TPE 72.566±0.110 / HEBO 72.696±0.060、対差 +0.130 (95%CI [+0.068, +0.199], 9勝1敗)
- best@40: TPE 72.659±0.074 / HEBO 72.721±0.037、対差 +0.062 (95%CI [+0.017, +0.111], 8勝2敗)
- サンプラー自体の計算: HEBO 109秒/40trial ≈ 2.7秒/trial(TPEは0.34秒/40trial)。
  ジョブが数十秒の本クラスタでは無視できるが、秒未満のtrialには不向き。
- 依存(numpy/pandas/torch系)のオフラインwheel持ち込みが必要な点が運用コスト。
注: 本検証は決定的目的関数(本番ブリッジと同条件)での結果。HEBOの主眼である
ノイズ頑健性そのものは別条件の検証が必要。

### 6. 動的スロット — 誤設定の自動回復と増方向の両方を実測
実際に supervise_slots.py + worker.py を起動して測定(シミュレーションではない)。
4コア機、CPUバウンドジョブ(CPU 3.5s, timeout 8s)/ sleepジョブ(2s)。

| シナリオ | goodput (成功/分) | 失敗数 |
|---|---|---|
| 12スロット固定 (過剰) | **0.0** | 444 (全timeout) |
| 12開始 + adapt | **53.4** | 82 |
| 4スロット固定 (理想値既知) | 67.6 | 0 |
| 4スロット固定, sleepジョブ | 118.7 | 0 |
| 4開始 + adapt, sleepジョブ | **192.0** (+62%) | 0 |

AIMD軌跡(実ログ): 12→9→6→4 で回復後、+1ずつ上限を探り9でtimeout検知→6。
発振により理想固定値には−21%及ばないが、「理想値を知らない/負荷が変わる」状況で
致命的な0 goodputを防ぐ保険として機能する。`--adapt` を付けない限り従来と同一動作。

## mainへの採用優先順位(実測に基づく)

1. **#1 TPE推奨設定** — 有意な改善 (+0.0282, CI下限+0.011)、変更は数行、
   失敗モードなし(`--tpe-profile default` で復元)。即採用。
2. **#2 のCI表示(mean既定+CI95列)** — このクラスタの存在目的である
   「実装A/Bどちらを本戦に使うか」の判定を守る。宣言時精度98〜100%、
   標準ライブラリのみ。※IQM既定化は実測に基づき撤回済み。
3. **#4 事前分布注入** — 本戦のような短い持ち時間で序盤有意 (+0.101@10trial)、
   誤priorでも回復を確認。opt-in(specに書かなければ無効)なのでリスク限定。
4. **#6 動的スロット** — 誤設定時 goodput 0→53.4/min、I/O型+62%。opt-inフラグ。
   採用価値は高いが探索品質ではなく運用の保険なので4位。発振(理想比−21%)が
   気になる場合は上限探り増加を止める保守設定も可。
5. **#5 HEBO** — 改善は有意 (+0.062, CI下限+0.017) だが、オフラインwheel持ち込みの
   運用コストと2.7s/trialのオーバーヘッドがあるため「TPEで頭打ちのときの選択肢」
   として採用。
6. **#3 successive halving** — **不採用**。同一予算で有意に悪化 (−0.042, CI上限−0.021)。
   5インスタンス構成では低忠実度評価のノイズが利得を食う。多インスタンス条件で
   要再検証(ブランチは保存)。

```
cd experiments && ../venv/bin/python validate_tpe_profile.py
```
